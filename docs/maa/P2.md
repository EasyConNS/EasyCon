# Maa P2：旧标签与 OCR 试点

2026-10-19。P2 初版基于 dev `d00b9284`，延续已合并 PR #78 的 P0/P1；本批验收修复基于最新 dev `3f5f8329`。原生运行库固定 5.14.3、C# binding 固定 5.10.0。本文描述已接入的产品路径；完整游戏与日文 OCR 兼容验收仍需对应素材和实机。

## P1 复验修复

- 同一有效采集后端的重复覆盖保留稳定来源 ID；显式换索引或换后端才清除旧身份。重排后按 ID 重新解析当前索引。
- GUI 配置恢复和 CLI profile 共用校验，拒绝互相矛盾的来源后端/缓存索引、负索引和未知后端。重新解析后的新索引不参与保存快照的一致性比较。
- `NeedIL` 保留编译器原义。宿主从链接结果判断实时采集需求：标签、FRAME、坐标 OCR 需要采集；已有图片 ROI、仅 OCR_INIT 不需要。ROI 无论是否连接采集都能装配。

## 标签转换

```powershell
# 参数是 ImgLabel 目录本身，不会再追加 ImgLabel
ezcon labels convert ./ImgLabel --output ./.easycon/maa-cache --compatibility LegacyGui
# 递归仅用于显式批量盘点；GUI/CLI 运行的标签来源不递归
ezcon labels convert ./project --recursive --output ./converted
```

命令严格处理全部错误，失败退出 1，输出 JSON 报告，不覆盖上次 `current.json`。运行入口允许保留未使用的坏标签，但编译实际引用的名称必须通过预检。

按旧入口的有序父目录追加 ImgLabel；同名时第一个成功解析的标签胜出，坏 JSON 不占名，已解析但不支持的标签保留错误身份。源 IL/ECS/Flow 不改写。默认派生缓存位于本机 LocalApplicationData 下的 `EasyCon/maa-cache/<项目路径摘要>/`。

generation 包含 `pipeline/legacy.native.json`、`legacy.compat.json`、bootstrap、内容摘要命名的 PNG，以及 `easycon/` 下的索引、报告与 manifest。转换器 `easycon.labels/3` 的摘要包含来源绝对路径、内容、优先级、转换器版本、运行库组合、规范化、兼容 profile 和模型摘要；来源路径与不可变索引一致，相同内容迁移目录会生成新版本。写临时目录、真实 Maa 装载预检后再发布目录并原子更新指针。复用时校验模板、节点、索引、报告和模型；损坏缓存明确失败。当前版本及运行中的旧版本保留，其余本转换器版本的标签缓存最多保留七份。

每个识别会话以 .NET 文件 API 读取并校验模板摘要，经 Maa `OverrideImage` 注册原生内存图像，避免固定 Windows runtime 的模板文件长路径限制；不依赖短文件名、符号链接或切换进程工作目录。原生需要读取的 Pipeline 元数据与模型复制到会话拥有的短 TEMP 目录，Tasker/Resource 排空释放后删除；源 generation 保留。Windows 装载路径超出保守预算时明确失败，可配置更短的 TEMP，不会继续伪装资源就绪。大于 64 KiB 的 Pipeline 与长来源路径组合另有真实回归，避免仅以小文件样本宣称长路径通过。

发布预检和运行会话都对每张不同的原生模板执行一次真实 `TemplateMatch` 自匹配探针，确认模板已装入同一资源。缺失、损坏、解码/探针失败会阻止发布或启动；未验证模板引用、过小 ROI、原生作业失败会明确报错。`ValidatedTemplates` 与 `NativeResourceDirectory` 可用于记录实际覆盖数和原生装载位置。原生候选为空只在资源已验证后按候选策略处理，负相关样本的正常空结果仍由兼容查询给出旧分数。

## 评分和路由

GUI 运行与标签预览已使用 `MaaVisionService`，CLI `run` 使用同一路径。显式图像查询把**识别类型和参数**传给 `AppendRecognition`；资源节点名供 Pipeline 使用。

| 旧方法 | 旧浮点分数 | 执行策略 |
|---|---|---|
| 5 CCoeffNormed | `((r+1)/2)*100` | Maa TemplateMatch 后同帧兼容确认 |
| 3 CCorrNormed | `100*r` | 同上 |
| 1 SqDiffNormed | `100*(1-r)` | 同上 |
| 14 透明匹配 | `100*(1-r)` | CustomRecognition 使用原 alpha 掩码 |
| 11/12 边缘匹配 | `((r+1)/2)*100` | CustomRecognition 使用原预处理 |

只有 `LegacyAlgorithmAdapter` 执行浮点和整数转换。LegacyGui 截断，LegacyCli 向上取整；CLI 支持 `run --compatibility` 显式固定。负分不钳零，NaN/Infinity 报诊断。当前没有跨平台误差上界，因此普通方法也执行同帧旧算法确认；这会增加计算成本，不能称为纯 Maa 原生匹配。

无 native best 不能返回零分。路由记录 `native-no-candidate`、`integer-boundary`、`best-box-semantics`、`native-verified`、掩码/预处理原因。每次查询只借一帧，PNG、frameId、sourceEpoch 固定，ROI 坐标以 1920×1080 整图解释，最终框只加一次偏移。追踪仅保存最后一项，可订阅事件自行持久化。

兼容查询的 hit=true 只代表计算有效。新 Pipeline 如需复刻旧整数条件，用 `MaaLabelConverter.ScoreCondition(entry, ">", 90, profile)` 生成 Custom 参数，识别类型为 `Custom`；扩展 `EasyCon.LegacyScoreCondition` 另外判断比较符及阈值。未配置业务阈值的查询节点不应当作成功条件。

原生标准节点可复用；直接将资源交给其他 Maa 宿主时，宿主需保证其模板路径可读或采用同样的内存装载。兼容节点依赖 EasyCon 注册的扩展，不能作为任意 Maa GUI 独立运行包。

## OCR 试点与启用

```powershell
# 唯一联网步骤：显式下载固定版本、固定 SHA-256 的官方中英 PP-OCR v4
ezcon maa models install ./maa-ocr-pilot
ezcon maa doctor --ocr-profile ./maa-ocr-pilot/ocr-profile.json
ezcon run ./script.ecs --ocr-profile ./maa-ocr-pilot/ocr-profile.json
# GUI：从设置了此环境变量的进程启动
$env:EASYCON_MAA_OCR_PROFILE = (Resolve-Path ./maa-ocr-pilot/ocr-profile.json).Path
```

安装目录含 det/rec/keys、profile、模型来源说明和 MaaCommonAssets/PaddleOCR 许可证。安装器保留已经存在的 profile。普通运行不会下载模型；profile 中的模型摘要必须匹配，核验后复制为固定版本，运行时编辑源文件不改变已有会话。

试点 profile 只声明 `chi_sim` / `eng`、Tessdata 路径别名、DEFAULT 引擎与 SINGLE_LINE 页面模式，采用 `only_rec`。其它语言、路径或选项没有唯一映射时初始化失败。`.traineddata` 不会当作 ONNX 模型加载。文字标签使用相同 profile 的 chi_sim 映射，在 Custom 回调内调用当前 Context 的 OCR 节点，保留 Trim、编辑距离及置信度相乘逻辑，不设置 expected 过滤。

`MaaOcrService` 接受调用方的图片，不借用控制器或摄像头。宽高 <=0 表示从收敛后的 X/Y 到图片边界；空区域保留 `OCR ARGS ERR!`。无效图片/普通失败返回空串并记日志，取消单独传播。成功结果更新 LastConfidence（原始均值×100，截断），提前返回、失败和仅 Init 保留先前置信度。普通文本不额外 Trim。每次独立 ECS 调用有新 OCR 状态，Flow 的 script.run 也创建独立状态。

**中英模型仅为试点，PP-OCR 与 Tesseract 的文本/置信度数值等价尚未证明；日文模型未配置。** 未显式启用 profile 时保留原 OCR 默认后端。NET_*、FFI、张量及旧字形算法维持原实现。

## 生命周期、验证与范围

识别使用专用无硬件 Tasker，串行执行，等待队列上限 32；脚本请求不丢弃。每次复制托管结果、排空取消/Stop 作业并释放图像后清原生历史。可观察等待数、活动图片数、保留结果数、识别会话数、活跃标签资源版本数及 OCR 模型资源数；这些宿主管理计数不冒充 Maa 内部模型对象计数。

```powershell
./ci/prepare-maa-ocr.ps1 -Configuration Release
dotnet test EasyCon2.slnx -c Release
dotnet format --verify-no-changes
```

Windows/macOS CI 强制安装真实模型并执行 OCR 测试，缺模型导致失败。dev 验收包携带 `maa-ocr-pilot`，默认不自动启用。原有 C VM 32/64 位差分门禁保留。

自动化覆盖真实 Maa 模板/OCR、两种整数 profile、无候选补救、掩码/边缘、条件 hit、缓存事务/编辑/损坏/旧版本引用、停止与结果清理，以及旧 ECS 分支到 fake IConnection 的最终 HID 字节。静态盘点和有限真实截图对拍另行记录，不能替代每标签正例/近似负例或完整游戏验收。

连接区的短状态、固定宽度选择框和完整名称 tooltip 已纳入生产文件。经典布局最小宽度的连接标题及按钮文字会在既有区域内收敛，卡片布局按钮同样适配可用宽度。M18 渲染/悬停/同名来源键盘选择的显式测试位于 `ConnectionPanelRenderTests.cs`；使用测试连接服务，不表示真实设备已连接。

本地实际素材对拍：1164 个有效标签×3 张原始 1080p 游戏截图，共 3492 项；旧浮点、GUI 整数、CLI 适配整数和最佳位置均无差异，每种方法×每帧另用实际 LegacyCli 服务检查，共 15 项。1340 项 native 原始分数存在数值差别，样本最大绝对差为 `0.0001233582372665437`；该值不是跨平台误差上界。1086 项没有 native 候选，106 项 native 最佳框与旧选择不同，均由同帧兼容结果保留旧行为。1218 个源 IL/ECS/Flow 文件前后摘要一致。复现工具见 [MaaReplayCheck](../../tools/MaaReplayCheck/README.md)。

当前真实 1165 标签包中 `正在进化.IL` 的模板为 313×36，ROI 为 232×131，旧 OpenCV 也不能执行该尺寸组合。转换报告保留错误，引用它的脚本在运行前失败，等待正确模板/范围；不会自动改写原包。日文 OCR、旧 OCR_CONF 阈值、全标签业务覆盖、真实 Mac 摄像头与 30 分钟游戏流程仍待验收。P3 RunEcs 与 P4 Flow 编排不包含在本阶段。

## 下一批执行器拆分的契约

按 2026-10-19 的设计修订，正式执行端只有 PC 高层执行与 MCU C VM。先形成不经过 ECX 编码的完整项目 IR，再实现桌面高层执行；MCU 沿独立降低/导出/目标预检路径生成 ECX。C VM 的桌面宿主用于模拟 MCU 内核；旧 C# EcxVm 只作迁移工具，不增加长期第三端或三方对拍要求。本批仍使用迁移期执行入口，没有将上述结构计为已经实施。手柄与采集的重建随后分别交付验收。
