# 喷射战士画板

画板把一张图片转成黑白点阵，通过虚拟手柄在《喷射战士》（Splatoon）的投稿画板上自动逐点画出来。画布固定为 **320×120** 个点；开画前先把光标推到左上角，再用方向键逐格移动，按住 A 画、按住 B 擦。

入口：主窗口“功能中心”→“喷射战士”。

## 快速上手

1. 在主窗口连接单片机，确认手柄能控制 Switch。
2. 打开“功能中心”→“喷射战士”，点击“加载图片”，或直接把图片拖进窗口。
3. 看预览：黑点就是要画的点。黑点太多或太少时，在“黑白”页调整阈值。
4. 在游戏里进入画画界面，**把笔刷调到最小**。光标不用手动对位，开画前程序会自动把它归位到左上角。
5. 点击“开始画图”。绘制期间手柄由画板独占，不要操作游戏。

画一张图通常需要几十分钟到两个多小时，预览下方会显示预计耗时。

## 界面

从上到下依次是：

| 区域 | 内容 |
|---|---|
| 工具栏 | 加载图片、保存图片、显示原图、重置；开始画图、暂停 / 继续、停止 |
| 预览 | 320×120 的结果，拉伸到窗口宽度显示。未载入图片时中间提示可以拖入图片；绘制中显示进度和光标 |
| 状态行 | 左侧是绘制区域，右侧是预计耗时，图片或参数一变就自动更新 |
| 进度条 | 百分比、完成段数、已用时间、剩余时间 |
| 参数标签页 | 图片 / 明暗 / 黑白 / 绘制，顺序与处理顺序一致 |
| 底部提示 | 开始前的准备步骤 |

窗口可以自由缩放，预览会跟着等比放大缩小。窗口太窄、控件放不下时，最小高度会自动增加。

**重置**会把所有选项恢复为默认值，已载入的图片保留。画图过程中不能重置。

**保存图片**把预览中的 320×120 图片存为 PNG：
- 默认保存黑白结果。下次直接载入这张图，用默认参数就能得到完全相同的点阵，适合保存调好的结果。
- 勾选“显示原图”时，保存的是旋转、适配后的彩色原图。

## 图片处理

图片依次经过以下步骤处理，每一步都可以在预览里看到效果：

```text
原图 → 旋转 / 翻转 → 适配到 320×120 → 明暗调整 → 阈值 / 抖动 → 去杂点 → 轮廓 → 反转黑白
```

透明像素一律当作白色（不画）。

### 支持的格式

PNG、JPG、BMP、GIF（取第一帧）、WebP、ICO、WBMP。

### “图片”页

- **适配**：任意尺寸的图片都会缩放到 320×120。
  - **等比留白**（默认）：整张图完整放进画布，不变形，多出的部分留白。
  - **等比裁切**：铺满画布，不变形，超出的部分裁掉。选中后会多出一行取景调整：
    - 角度：任意角度旋转，范围 −180° 到 180°。
    - 缩放：100% 到 400%。
    - 左右、上下：调整取景位置。
    - 重置取景：恢复居中、不旋转、不放大。
  - **拉伸**：直接拉成 320×120，比例会变。
- **原图尺寸**：适配方式旁边显示原图的宽高。
- **旋转、水平翻转、垂直翻转**：以 90° 为单位顺时针旋转原图，翻转按旋转后的方向进行。
- **像素画（最近邻缩放）**：缩放时不做平滑处理。像素画、点阵图放大后边缘不会出现灰色过渡，线条不会变粗或断开。照片不建议勾选。

### “明暗”页

在转成黑白之前调整图片的明暗，适合偏暗或偏灰的照片。

| 选项 | 范围 | 作用 |
|---|---|---|
| 亮度 | −100 到 100 | 整体变亮，墨点变少；整体变暗，墨点变多 |
| 对比度 | −100 到 100 | 调高时明暗差别拉大，灰色更容易分到黑或白 |
| 伽马 | 0.2 到 3（默认 1） | 大于 1 提亮暗部，小于 1 压暗亮部；纯黑和纯白不受影响 |

“重置明暗”把这三项恢复为默认值。

### “黑白”页

- **阈值**（默认 50%）：比这个亮度暗的点画成黑点。调高会多画，调低会少画。
- **抖动**：用黑点的疏密表现灰度，照片效果更好，但点更碎、画得更久。

  | 算法 | 特点 |
  |---|---|
  | 关闭（默认） | 只按阈值分黑白，线段最少，最快 |
  | Floyd–Steinberg | 最常用的误差扩散 |
  | Floyd–Steinberg（蛇形） | 逐行换向扫描，减少斜向纹理 |
  | Atkinson | 点最少、对比强，抖动算法里最快 |
  | Jarvis–Judice–Ninke | 过渡最平滑 |
  | Stucki | 与 JJN 接近，略锐利 |
  | Bayer 有序 | 规则的网格图案 |

- **去杂点**（0 到 20，0 为关闭）：去掉总点数不超过这个值的孤立墨点块（上下左右和斜向相连算一块）。用来清理抖动后浅色区域的零散点，能明显减少线段数和耗时。
- **轮廓模式（只画边缘）**：只保留墨点区域的边缘，实心部分挖空。线条和单点不受影响；画布边缘不算轮廓。
- **反转黑白**：最后一步，把处理完的结果黑白互换。例如轮廓模式加反转，会得到黑底白线。

## 绘制设置

在“绘制”页。

### 按键持续与延迟

| 参数 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| 按键持续 | 50 毫秒 | 1 到 10000 | 每次点按方向键时按住的时间 |
| 延迟 | 45 毫秒 | 0 到 10000 | 每次按键后的等待时间 |

默认值在有线连接的 ESP32-S3 上验证过。调得太小，游戏可能来不及响应，出现漏格、错位；蓝牙连接的设备尚未验证，出现错位时请先调大这两项。输入不是有效数字时，右下角显示“参数有误”，开始画图时会提示是哪一项、允许什么范围。

### 橡皮擦模式

适用于“黑多白少”的图：先在游戏里把画布整个涂黑，再让程序按住 **B（橡皮擦）** 擦出图中的白色部分，最终效果与画笔模式相同。

准备步骤（鼠标悬停在复选框上也能看到）：

1. 在游戏里用最大笔刷把整张画布涂黑。
2. 把笔刷调到最小。
3. 勾选“橡皮擦模式”后开始画图。

勾选后右下角的耗时会按要擦的点重新估算，可以对比两种模式选更快的一种。

### 开画前自动归位

默认勾选。开画前自动把光标归位到画布左上角，并防止开头的输入因丢帧而失效，会多花几秒。

**强烈建议保持勾选。** 取消勾选时会弹出风险提示：Switch 可能丢掉开头的输入帧，即使开始前手动把光标移到了左上角，也可能出现不可预测的绘制错位或整行缺失。

### 框选绘制区域

默认画整张画布。勾选“框选绘制区域”后，在预览上按住鼠标拖动，就只画框住的部分：
- 预览上会用橙色框标出区域，状态行显示区域的起止列和行。
- 点击“全图”恢复为整张画布。
- 绘制中不能修改区域；停止或画完后可以重新拖动框选。

无论是否框选，程序都先把光标推到画布左上角，再空走到区域内。

适合补画：先画完一遍，发现某块有漏画或错位，框出那一块再画一次。

## 绘制过程

点击“开始画图”后：

- **独占手柄**：画图与脚本运行使用同一套独占机制。
  - 脚本运行时无法开始画图；画图时虚拟手柄、键盘映射等手动输入也被挡住。
  - 画完、停止或出错时，程序会松开所有按键。
- **归位**（可关闭，见上）：开画前先把光标归位到画布左上角。
- **顺序**：从上到下逐行画，每行把连续的黑点作为一段，按住 A 一笔画完。每一段从离光标近的一端开始。
- **进度**：进度条显示百分比、第几段 / 共几段、已用时间、剩余时间。剩余时间按本次实测的每类操作额外耗时计算，见下节。
- **实时预览**：

  | 显示 | 含义 |
  |---|---|
  | 黑色 | 已画的点 |
  | 灰色 | 还没画的点 |
  | 红点和红框 | 光标当前位置 |
  | 很浅的灰色 | 框选区域以外的点（本次不画，只作对照） |

  橡皮擦模式下颜色反过来：已擦的点为白、待擦的点为深灰。
- **暂停 / 继续**：暂停在下一次按键前生效，手柄仍然被占用。如果暂停时正按着画笔，会先抬笔，继续时在原位重新落笔。暂停的时间不计入用时。
- **停止**：立即停止并松开按键，进度条显示停止时完成的百分比。
- **关闭窗口**：同样会立即中止绘制。

绘制开始时会取当前图片和参数的快照。画图过程中调整阈值、切换模式等，不会影响正在画的这一张。

## 耗时与提速

预计耗时与实际发出的按键序列逐项对应，按默认参数：

- 光标每移动一格：按键持续 + 延迟 = **95 毫秒**。
- 每画一段线的固定开销：6 次延迟 = **270 毫秒**（落笔、抬笔，以及每次移动换方向后的等待）。

另有开画前归位约 4 秒。计划耗时约等于“4 秒 + 总移动格数 × 95 毫秒 + 线段数 × 270 毫秒”。

实际会比计划慢：每次点按、落笔、抬笔都要和设备通信一次，计时也有误差。线段越多（比如抖动图），落笔、抬笔越多，慢得越明显。所以程序按操作类别分别统计额外耗时：

- 绘制中，每次点按、每次落笔/抬笔、每次延迟各实际多花了多少，都会实时统计。剩余时间等于剩下各类操作的次数乘以对应的实测值，再加上剩余的计划耗时。这样不会因为图案前疏后密而估偏。
- 画完或停止后，日志里会记一条“画板实测额外耗时”。之后的预计耗时会把这些额外耗时算进去。实测值在程序运行期间有效，重启后从 0 重新统计，因此第一次画图前的估算仍是计划耗时。

参考数据（整张画布，默认参数）：

| 图案 | 线段数 | 耗时 |
|---|---|---|
| 全黑 | 120 | 约 61 分钟 |
| 棋盘格（最坏情况） | 19200 | 约 147 分钟 |

400×400 径向渐变图（等比裁切）在各抖动算法下的耗时：

| 抖动 | 线段数 | 耗时 |
|---|---|---|
| 关闭 | 120 | 约 28 分钟 |
| Atkinson | 7066 | 约 81 分钟 |
| Floyd–Steinberg | 10494 | 约 103 分钟 |
| Bayer | 10571 | 约 103 分钟 |

抖动后再开启去杂点，同类图片的耗时实测还能减少约 20%。

提速的办法：
- 线段越少越快。能不用抖动就不用；必须用时选 Atkinson，并开启去杂点。
- 黑多白少的图改用橡皮擦模式。
- 只需补画一部分时，用框选绘制区域。
- 有线连接且稳定时，可以尝试调小延迟，但要留意漏格。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 提示“串口未连接” | 先在主窗口连接单片机 |
| 提示手柄正被占用 | 有脚本在运行，先停止脚本 |
| 提示图片加载失败 | 格式不支持，转换成 PNG 或 JPG 后再试 |
| 画出来整体错位 | 笔刷不是最小；或开画时不在画画界面，归位没有生效 |
| 越画越偏、漏格 | 游戏没跟上按键。调大延迟或按键持续，蓝牙设备尤其注意 |
| 画到一半停了 | 进度条显示停止时的百分比，出错时会弹框说明原因并写入日志；可以框选未完成的区域补画 |
| 预览一片黑或一片白 | 阈值太高或太低，或勾选了反转黑白；也可以点“重置”从默认值重新调 |
| 抖动后耗时特别长 | 换 Atkinson，开启去杂点，或关闭抖动 |

## 实现说明（维护者）

代码位于 `src/EasyCon2.Avalonia/DrawingBoard/`，从 1.6.3 WinForms 版 `DrawingBoard` 移植，修复了旧版缺陷（停止不立即生效、关窗后继续画、第 0 列单点画成整行、耗时少算、透明当黑等）。

| 文件 | 职责 |
|---|---|
| `SplatoonDrawing.cs` | 扫描（`SearchLines`）、估算（`EstimateCost`，用空手柄跑同一套按键序列，得到计划耗时与各类操作次数）、绘制（`Draw` / `Home` / `MoveTo` / 暂停）、额外耗时实测（`Overhead`，按点按 / 落笔抬笔 / 延迟分类） |
| `InkMask.cs`、`InkMask.Filters.cs` | 二值化、反转、去杂点（8 连通）、轮廓（4 邻域，画布边缘不算轮廓） |
| `Dithering.cs`、`ToneAdjust.cs` | 抖动算法；明暗调整 |
| `PreviewOverlay.cs` | 绘制进度图与区域框 |
| `DrawingRunner.cs` | `IDrawingRunner`：经 `HostRunCoordinator` 取运行租约，与脚本互斥 |
| `DrawingBoardViewModel*.cs` | 按职责分为 核心 / Picture / Adjust / Settings / Drawing 五个分部文件 |
| `DrawingBoardWindow.axaml(.cs)` | 布局；代码后置只做指针坐标换算与最小高度计算 |

归位（`Home`）：左摇杆以最大角度（X、Y 都为 0）推向左上，先推 50 毫秒，再推住 4 秒，每次回中后等一次延迟。第一下用来“垫帧”：Switch 可能丢掉连接后的第一帧输入，丢的是这一下也无妨；如果第一下就是落笔，丢帧会让第一行整行画不出来（真机上遇到过）。第二下把光标从画布任意位置推到左上角。

测试：
- `test/EasyCon2.Avalonia.Core.Tests/DrawingBoard*`：算法、图片处理、参数、运行过程，用假手柄记录按键。
- `test/EasyCon2.Avalonia.UiTests/DrawingBoardWindowTests.cs` 等：无头渲染下的布局与交互，检查各标签页在最小尺寸下不溢出、预览缩放与坐标换算。
- 所有用到的 `Text.DrawingBoard.*` 文案键必须在 `zh_CN` 和 `en_US` 中同时存在，由测试检查。
