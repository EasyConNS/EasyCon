# 声音标签

在主窗口的“游戏音频”面板点击“声音标签”，可以录制新声音，也可以从最近的游戏声音创建音效样本。经典布局和卡片布局均提供入口。

## 创建标签

1. 选择并连接游戏音频输入。应用持续在内存缓存最近最多 15 秒，无需提前打开标签窗口。
2. 在“声音标签”窗口点击“开始录制”，再去游戏中触发目标音效，结束后点击同一位置的“停止录制”。按钮旁显示已录时长和本次上限，停止后生成可编辑波形。每次最多录制 15 秒，同时受 16 MiB 音频数据上限约束；高采样率、多声道时按显示的较短时长自动停止，保留从点击开始起的声音。若目标声音已经响过，也可以打开窗口或点击“截取最近 10 秒”回看最近声音；尚未积累 10 秒时使用现有数据，并显示实际时长。
3. 在波形上拖动框选完整音效，拖动左右边界调整，或直接输入开始、结束时间。波形显示所有声道的幅度包络；试听仍保留原始声道。
4. 点击“试听选区”。声音通过 Windows 默认输出设备播放，红色游标和下方读数随实际播放位置更新，时间刻度对应整段录音。例如试听第 3～5 秒时，游标从第 3 秒开始。播放期间按钮变为“暂停试听”，点击后声音和游标停止，再点击“继续试听”从游标处接着听。输入源没有扬声器监听；只有主动试听才播放。
5. 输入名称，点击“保存选区为标签”并选择目录。建议放在脚本旁的 `audiolabel` 目录中。已有同名标签不会被覆盖，修改后请使用新名称或目录保存。

“打开 WAV / 声音标签”可载入 PCM 8/16/24/32 bit 或 float32 WAV，或打开已保存标签中的 `label.json`。音频数据上限为 16 MiB。不支持压缩 WAV。非 Windows 平台可以打开、裁剪和保存已有文件，但暂不提供实时采集与试听。

录制期间不能截取历史、打开文件、编辑选区、试听或保存，完成后恢复。录制中断、重连、收到无效音频或超过 1 秒没有新数据时会报错，已有音频和选区会保留；没有录到数据时停止也不会生成空标签。静音采样仍是有效音频。

录制和截取都是独立副本，编辑期间采集继续运行。裁剪按完整采样帧对齐，保留原始采样率、声道和位深，不重采样、不做增益或降噪。保存始终使用完整选区，试听时移动游标不会改变保存内容。关闭窗口会取消录制、停止试听并释放编辑副本；音频源继续采集。请在关闭前保存需要保留的选区。

## 暂停、定位与快捷键

- 暂停后单击波形，或拖动红色游标，可以前后定位。“继续试听”从新位置播放到选区末尾。例如选区是第 3～5 秒，在第 4.2 秒暂停后单击第 3.6 秒，继续就从第 3.6 秒开始；保存仍保留第 3～5 秒。
- 游标只能定位到选区内，点击外侧会停在最近的选区边界。游标与裁剪边界重合时，可拖动顶部红色小手柄移动游标，拖动下方边界线调整裁剪。拖动其他波形区域仍用于重新框选，开始、结束时间也可以直接输入。改变选区会结束暂停状态，下一次试听从新选区起点开始。
- “停止试听”结束本次试听，保留当前位置供参考；下一次试听从选区起点开始。停止后也可单击波形指定新的试听起点。播放到选区末尾自动结束；在末尾继续不会自动循环。
- 空格切换播放／暂停／继续，长按只执行一次。即使焦点在“截取最近 10 秒”“开始录制”等按钮上，也不会触发这些按钮；尚无音频或正在录制时，空格不执行操作。标签名称和时间输入框保留自身的输入行为，要用空格控制试听时先点击波形或试听按钮。

## 实时匹配测试

1. 在主窗口的“游戏音频”面板连接输入，点击“声音匹配测试”。经典布局和卡片布局都有入口。
2. 点击“打开 WAV / 声音标签”，选择标签目录里的 `label.json`，也可以直接打开 WAV。测试模板需为 0.15～10 秒，包含完整且清晰的目标音效；静音和缺少有效特征的文件会被拒绝。
3. 点击“开始监听”，等候积累完整音效长度的新音频，然后在游戏中触发目标声音。监听从点击开始后的新数据计算，不会拿制作标签时的历史声音重复测试。
4. 查看“当前匹配分数”“本次最高分”和命中记录。当前分数是最近一批音频（通常约 100 ms）中最佳对齐位置的分数；没有完整、有效音频时显示 `—`。命中记录保存首次达到阈值时的分数、当时阈值和电脑检测时间，最近 100 条保留在内存。
5. 初始阈值是 0.85，可以在监听时调整。连续高分只计一次；分数下降到阈值以下 0.05 后才允许再次触发，并受“命中间隔”限制（默认 1 秒）。调整只影响后续音频，不会重新判定旧结果。
6. 点击“停止监听”保留结果；再次开始会清空本次结果。“清空结果”只重置界面统计，不重新触发正在响的同一次音效。关闭测试窗口会停止匹配，不会断开主窗口的音频输入。

先重复触发目标声音 5～10 次，检查是否漏报；再播放普通游戏声音和背景音乐，检查是否误报。根据两组分数调整阈值。如果分数混在一起，仅改阈值无法可靠区分，应重新截取背景干扰更少的模板。不要仅通过在电脑上回放模板来认定游戏识别已验证：真实游戏混音和音量变化还需单独测试。

匹配使用托管频谱模板比较：带滤波的 8 kHz 重采样、32 ms Hann 窗、10 ms 步长，合并各声道的频谱功率后提取归一化特征。左右声道反相不会因直接混为单声道而抵消。特征主要覆盖约 94～4000 Hz，分数范围为 0～1，表示相似度，不是出闪概率。归一化能减轻音量变化的影响，不能分离重叠的背景音乐、恢复被噪声淹没的音效或适应任意速度变化。

实时匹配复用已有采集设备，在后台线程处理。输入队列限制为 2 秒、4 MiB 或 256 块；积压、无效样本、断线、会话或格式变化以及超过 1 秒未收到新回调时清空旧数据，重新积累完整窗口。采集接口没有硬件缺包标记或精确样本时间戳，不能保证发现所有短暂中断；检测时间也不是精确的游戏事件时间。非 Windows 平台可以加载模板，暂不支持实时监听。

## 文件格式

每个标签是一个可整体移动的 `<名称>.audiolabel` 目录，包含：

- `audio.wav`：裁剪后的原始音频。
- `label.json`：版本（当前为 1）、名称、音频格式、采样帧数及 UTC 创建时间。

保存先写入临时目录，两个文件完整写入后一次性发布目录；文件写入失败不会留下一个看似完整的新标签，也不会覆盖旧标签。打开时校验 JSON 与 WAV 的格式和长度是否一致。修改标签后另存为新的目录。

## 范围与边界

当前提供样本制作、实时匹配测试及 ECS 的 `AUDIO` / `AUDIO_WAIT` / `AUDIO_WAIT_SCORE` 函数。实时匹配窗口只展示分数和命中记录；脚本通过这些函数读取结果并明确决定后续动作。仍需使用实际游戏的正、负样本校准。背景音乐与目标音效同时出现时，裁剪不能把两者分离，应尽量采集背景干扰小的样本。

编辑器缓存借用现有 `IAudioCaptureSource`，不创建第二个采集设备。编辑器按完整采样帧裁剪，同时受 15 秒与 16 MiB 上限约束。断开、重连、格式变化、无效数据或超过 1 秒没有新回调时丢弃旧历史；陈旧数据不能作为“最近音频”截取。编辑器缓存不参与脚本检测；脚本使用下面的独立时间线。

## ECS 窗口边界与限制

函数签名、调用示例见[函数手册](Functions.md#声音匹配桌面-gui需连接游戏音频)。将标签保存到入口脚本目录下的 `audiolabel/<名称>.audiolabel/label.json`，名称不带路径。脚本必须先保存；从编辑器运行未保存的修改仍以该入口文件所在目录为基准。每次运行按需加载模板，最多缓存 32 个；修改标签后重新运行脚本。

可直接运行的完整脚本：[回看并打印最高分](../examples/audio-lookback.ecs)、[等待命中或超时](../examples/audio-wait.ecs)、[等待后读取最高分](../examples/audio-wait-score.ecs)。函数手册包含目录结构、预期行为及多轮结果保存示例。

- `AUDIO(name, lookbackMs)`：查询调用时刻之前 1～15000ms 内的最高原始分数，不等待、不消费历史。执行操作前订阅本次运行的新数据，因此按键和 `WAIT` 期间的声音可以查询。未积累满请求时长时，起点收缩到本次运行的有效数据起点；不足完整模板特征时抛错误。PCM 同时受 16MiB 和 4096 块上限限制，高采样率/多声道时实际保留可能短于 15 秒，查询已丢弃部分会报错。
- `AUDIO_WAIT(name, timeoutMs, threshold = 0.85)`：范围 1～300000ms；独立订阅、独立预热，只接收调用后的新音频。首次模板加载、等待和分析共用从调用开始计算的一个截止时间。只有在截止前完成并确认达到原始阈值才返回 true；输入有效且已产生完整模板分数时，到期未确认命中返回 false。到期不再分析尚未处理的末尾音频，不接受截止后完成的结果，不增加处理宽限。false 表示“指定时间内未确认命中”，不能证明末尾每个采样都已分析。末尾正常的少量排队不报错，积压超过 250ms 音频仍报错误；该数值只用于检查积压量，不增加等待时间。尚未完成一个完整模板的分析会提示脚本作者增大 timeoutMs，应用不会自动放宽参数。每次调用释放自己的监听，运行结束再释放运行缓存；从不停止共享音频源。
- `AUDIO_WAIT_SCORE()`：读取最近一次正常结束的等待中，截止前已完成分析的最高分；返回 DOUBLE，范围 0～1。命中提前返回时只统计实际等待期间，超时时不补算末尾数据。读取使用保存的标量，不增加监听或重新分析；重复读取不消费结果，`AUDIO` 查询不覆盖它。每次新等待开始先清除旧结果；尚未等待、等待出错或取消时读取报错，不能把失效结果当成 0 或沿用上一轮。结果按脚本运行隔离，无需设备保持连接即可读取已保存的正常结果；是否命中仍以 `AUDIO_WAIT` 的 BOOL 为准。
- 时间线：首个有效块的回调时间减去其采样时长作为估计起点，随后按累计采样数推进，使用单调时钟。跨越运行/调用起点的首块按采样帧裁掉旧部分；匹配窗口只包含位于所选边界内的完整 STFT 特征，不借用边界外的模板上下文。32ms 分析窗、10ms 步长可能导致不同起点下最佳对齐分数略有差别；模板末尾不足一个新分析步长的样本与测试窗口一样不形成额外特征。
- 数据有效性：单块最多 250ms；每块样本时钟与回调时间的偏差、回调交付延迟不能超过 250ms，时间戳必须递增；超过 1 秒没有新回调会使本次运行失效。等待的首包与最后一个截止前有效包离两端均需不超过 250ms，并且已经在截止前产生完整模板分数，才可返回 false。这些是输入有效性检查，不延长函数的截止时间。窗口末尾尚未处理的音频不会补算；超时太短、预热不足、静音之外的无数据均为错误。
- 会话隔离：每块携带生成它的不可变连接状态标识；上一设备会话或本次启动前的迟到块不能进入新缓存。断开/重连、格式变化、无效块、时钟中断使当前运行报错；需要重新运行脚本，不能靠重连把未知区间变成未命中。停止按钮通过取消令牌中断等待及特征计算，清理全部运行订阅。

静音 PCM 是有效输入，可以得到 0；没有音频包不是静音。音频检测与测试窗口复用 `AudioTemplateMatcher`，分数是 0～1 的相似度，阈值是 0.1～1，直接比较原始值。窗口的连续事件去重和冷却间隔不参与脚本一次性等待。

回看时最新有效回调距查询时刻也不能超过 250ms，否则报窗口末尾数据不足，即使更早的历史里已有高分也不会返回它。每个运行历史/独立等待缓冲区分别受上述 PCM 上限约束；同一脚本最多同时持有这两个缓冲区。

来源只有回调时间，没有硬件采样时间戳或缺包标志。250ms 是拒绝明显不可靠数据的容差，并非误差上界保证；无法发现所有短暂硬件缺包，也无法知道每个采样相对真实游戏事件的精确时刻。等待分析按最多 10ms 的采样量分批检查截止时间，避免处理整块音频后才发现超时。Windows/.NET 的线程调度、同步文件读取及单批计算仍可能产生执行延迟，不承诺硬实时返回，但程序不主动增加任何超时宽限。依赖严格亚块级事件边界的流程仍需硬件时间戳支持。当前 GUI 使用已经连接的游戏音频源；CLI 和单片机没有此能力，会明确拒跑。没有实测保证任何游戏的识别率。

## 验证

自动化测试覆盖缓存回绕、原始样本裁剪、重连隔离、陈旧数据、文件往返、拒绝覆盖，以及编辑器试听/保存选区一致性与取消清理。手动录制另外验证起点裁剪、仅采新音频、手动停止、时间/内存上限、异常保留旧选区和订阅释放。无头界面测试验证空格不误触按钮、长按去重、输入框行为、暂停后单击/拖动游标再继续、边界裁剪、录制按钮与计时，以及两种语言与亮暗主题；手动截图用例可用于视觉检查。真实采集卡、实际扬声器试听和设备热拔插仍需实机验收。

匹配测试另外覆盖不同采样率和 PCM 格式、音量变化、反相立体声、任意分块边界、无关音效与静音、重复命中抑制、队列积压、断线后过期结果作废，以及窗口关闭时的取消与订阅清理。合成音频测试不能替代实际游戏音效的识别率验证。

ECS 测试覆盖按键期间回看、重复查询、窗口外旧声、跨运行/重连隔离、新声音等待、原始分数与默认/非法阈值、到期不补算末包、不接受迟到结果、只有显式增大 timeoutMs 才延长识别机会、1/8 秒等待不增加后续执行时间、真实积压、无音频/预热不足、取消和释放，以及桌面能力接入、脚本旁标签加载、函数提示与 MCU 拒跑。等待分数另外验证命中/超时峰值、静音返回 0、多轮替换、回看不覆盖、重复读取不等待、读取前置条件、错误/取消后清除旧结果和跨运行隔离。末包测试包含 44.1/96 kHz 及 float32 输入；时间边界使用可控时钟验证，三个发布示例也参与编译验证。
