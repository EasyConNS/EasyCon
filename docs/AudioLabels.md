# 声音标签

在主窗口的“游戏音频”面板点击“声音标签”，可以从最近的游戏声音创建音效样本。经典布局和卡片布局均提供入口。

## 创建标签

1. 选择并连接游戏音频输入。应用持续在内存缓存最近最多 15 秒，无需提前打开标签窗口。
2. 听到目标声音后打开“声音标签”，或点击“截取最近 10 秒”。尚未积累 10 秒时使用现有数据，并显示实际时长。
3. 在波形上拖动框选完整音效，拖动左右边界调整，或直接输入开始、结束时间。波形显示所有声道的幅度包络；试听仍保留原始声道。
4. 点击“试听选区”。声音通过 Windows 默认输出设备播放，可以随时停止。输入源没有扬声器监听；只有主动试听才播放。
5. 输入名称，点击“保存选区为标签”并选择目录。建议放在脚本旁的 `audiolabel` 目录中。已有同名标签不会被覆盖，修改后请使用新名称或目录保存。

“打开 WAV / 声音标签”可载入 PCM 8/16/24/32 bit 或 float32 WAV，或打开已保存标签中的 `label.json`。音频数据上限为 16 MiB。不支持压缩 WAV。非 Windows 平台可以打开、裁剪和保存已有文件，但暂不提供实时采集与试听。

截取是独立副本，编辑期间采集继续运行。试听和保存使用同一个按采样帧对齐的选区，保留原始采样率、声道和位深，不重采样、不做增益或降噪。关闭窗口会停止试听并释放编辑副本；音频源继续采集。请在关闭前保存需要保留的选区。

## 实时匹配测试

1. 在主窗口的“游戏音频”面板连接输入，点击“声音匹配测试”。经典布局和卡片布局都有入口。
2. 点击“打开 WAV / 声音标签”，选择标签目录里的 `label.json`，也可以直接打开 WAV。测试模板需为 0.15～10 秒，包含完整且清晰的目标音效；静音和缺少有效特征的文件会被拒绝。
3. 点击“开始监听”，等候积累完整音效长度的新音频，然后在游戏中触发目标声音。监听从点击开始后的新数据计算，不会拿制作标签时的历史声音重复测试。
4. 查看“当前匹配分数”“本次最高分”和命中记录。当前分数是最近一批音频（通常约 100 ms）中最佳对齐位置的分数；没有完整、有效音频时显示 `—`。命中记录保存首次达到阈值时的分数、当时阈值和电脑检测时间，最近 100 条保留在内存。
5. 初始阈值是 0.85，可以在监听时调整。连续高分只计一次；分数下降到阈值以下 0.05 后才允许再次触发，并受“命中间隔”限制（默认 1 秒）。调整只影响后续音频，不会重新判定旧结果。
6. 点击“停止监听”保留结果；再次开始会清空本次结果。“清空结果”只重置界面统计，不重新触发正在响的同一次音效。关闭测试窗口会停止匹配，不会断开主窗口的音频输入。

先重复触发目标声音 5～10 次，检查是否漏报；再播放普通游戏声音和背景音乐，检查是否误报。根据两组分数调整阈值。如果分数混在一起，仅改阈值无法可靠区分，应重新截取背景干扰更少的模板。不要仅通过在电脑上回放模板来认定游戏识别已验证：真实游戏混音和音量变化还需单独测试。

匹配使用托管频谱模板比较：带滤波的 8 kHz 重采样、32 ms Hann 窗、10 ms 步长，合并各声道的频谱功率后提取归一化特征。左右声道反相不会因直接混为单声道而抵消。特征主要覆盖约 94～4000 Hz，分数范围为 0～1，表示相似度，不是出闪概率。归一化能减轻音量变化的影响，不能分离重叠的背景音乐、恢复被噪声淹没的音效或适应任意速度变化。

实时匹配复用已有采集设备，在后台线程处理。输入队列限制为 2 秒、4 MiB 或 256 块；积压、无效样本、断线、会话或格式变化以及超过 1 秒未收到新回调时清空旧数据，重新积累完整窗口。采集接口没有硬件缺包标记或精确样本时间戳，不能保证发现所有短暂中断；检测时间也不是精确的游戏事件时间。非 Windows 平台可以加载模板，暂不支持实时监听。

## 文件格式

每个标签是一个可整体移动的 `<名称>.audiolabel` 目录，包含：

- `audio.wav`：裁剪后的原始音频。
- `label.json`：版本（当前为 1）、名称、音频格式、采样帧数及 UTC 创建时间。

保存先写入临时目录，两个文件完整写入后一次性发布目录；文件写入失败不会留下一个看似完整的新标签，也不会覆盖旧标签。打开时校验 JSON 与 WAV 的格式和长度是否一致。修改标签后另存为新的目录。

## 范围与边界

当前提供样本制作和实时匹配测试，不包含 ECS 音频函数或自动判闪后触发脚本动作。实时匹配只展示分数和命中记录，仍需使用实际游戏的正、负样本校准。背景音乐与目标音效同时出现时，裁剪不能把两者分离，应尽量采集背景干扰小的样本。

缓存借用现有 `IAudioCaptureSource`，不创建第二个采集设备。缓存按完整采样帧裁剪，同时受 15 秒与 16 MiB 上限约束。断开、重连、格式变化、无效数据或超过 1 秒没有新回调时丢弃旧历史；陈旧数据不能作为“最近音频”截取。当前时间戳是回调时间，不能用于精确的脚本判定窗口，也不能证明底层没有发生短暂缺包。

## 验证

自动化测试覆盖缓存回绕、原始样本裁剪、重连隔离、陈旧数据、文件往返、拒绝覆盖，以及编辑器试听/保存选区一致性与取消清理。无头界面测试验证波形选择绑定、两种语言与亮暗主题，手动截图用例可用于视觉检查。真实采集卡、实际扬声器试听和设备热拔插仍需实机验收。

匹配测试另外覆盖不同采样率和 PCM 格式、音量变化、反相立体声、任意分块边界、无关音效与静音、重复命中抑制、队列积压、断线后过期结果作废，以及窗口关闭时的取消与订阅清理。合成音频测试不能替代实际游戏音效的识别率验证。
