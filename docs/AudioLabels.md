# 声音标签

在主窗口的“游戏音频”面板点击“声音标签”，可以录制新声音，也可以从最近的游戏声音创建音效样本。经典布局和卡片布局均提供入口。

第一次在脚本里使用时，先按[第一次在 ECS 中使用](#第一次在-ecs-中使用)准备目录；遇到加载或运行失败，查看[常见报错排查](#常见报错排查)。

## 创建标签

1. 选择并连接游戏音频输入。应用持续在内存缓存最近最多 15 秒，无需提前打开标签窗口。
2. 在“声音标签”窗口点击“开始录制”，再去游戏中触发目标音效，结束后点击同一位置的“停止录制”。按钮旁显示已录时长和本次上限，停止后生成可编辑波形。每次最多录制 15 秒，同时受 16 MiB 音频数据上限约束；高采样率、多声道时按显示的较短时长自动停止，保留从点击开始起的声音。若目标声音已经响过，也可以打开窗口或点击“截取最近 10 秒”回看最近声音；尚未积累 10 秒时使用现有数据，并显示实际时长。
3. 在波形上拖动框选完整音效，拖动左右边界调整，或直接输入开始、结束时间。用于 ECS 或实时匹配测试的选区必须为 0.15～10 秒，且包含有效声音特征；录制上限 15 秒不代表可以用 15 秒的标签匹配。波形显示所有声道的幅度包络；试听仍保留原始声道。
4. 点击“试听选区”。声音通过 Windows 默认输出设备播放，红色游标和下方读数随实际播放位置更新，时间刻度对应整段录音。例如试听第 3～5 秒时，游标从第 3 秒开始。播放期间按钮变为“暂停试听”，点击后声音和游标停止，再点击“继续试听”从游标处接着听。输入源没有扬声器监听；只有主动试听才播放。
5. 输入名称，点击“保存选区为标签”。当前已打开且已保存 ECS 时，直接保存到脚本旁的 `audiolabel`，不存在就自动创建，无需选择目录。没有打开脚本或脚本尚未保存时，选择准备存放 ECS 的文件夹，程序在里面创建 `audiolabel/<名称>.audiolabel`。保存后显示完整路径；已有同名标签不会被覆盖，修改后请使用新名称保存。

这里的“尚未保存”指新建脚本从未保存、尚无文件路径；已有 ECS 即使有未保存的内容修改，标签也会按其现有文件路径保存。

“打开 WAV / 声音标签”可载入 PCM 8/16/24/32 bit 或 float32 WAV（包括 WAVE_FORMAT_EXTENSIBLE 封装），或打开已保存标签中的 `label.json`。音频数据上限为 16 MiB。不支持压缩 WAV。非 Windows 平台可以打开、裁剪和保存已有文件，但暂不提供实时采集与试听。

录制期间不能截取历史、打开文件、编辑选区、试听或保存，完成后恢复。录制中断、重连、收到无效音频或超过 1 秒没有新数据时会报错，已有音频和选区会保留；没有录到数据时停止也不会生成空标签。静音采样仍是有效音频。

录制和截取都是独立副本，编辑期间采集继续运行。裁剪按完整采样帧对齐，保留原始采样率、声道和位深，不重采样、不做增益或降噪。保存始终使用完整选区，试听时移动游标不会改变保存内容。关闭窗口会取消录制、停止试听并释放编辑副本；音频源继续采集。请在关闭前保存需要保留的选区。

## 第一次在 ECS 中使用

ECS 根据**已保存的入口脚本所在目录**查找声音标签。直接在窗口里打开或测试过标签，并不会把它自动关联到脚本；软件安装目录和最近打开文件的位置也不决定查找路径。

以标签“闪光音效”为例，按以下步骤准备：

1. 新建自己的脚本目录，例如 `D:\游戏脚本\闪光测试`，把脚本保存为其中的 `test.ecs`，并保持这个脚本打开。后续运行这个入口文件。
2. 新制作标签时，在编辑器中输入名称 `闪光音效`，点击“保存选区为标签”。程序直接在 `D:\游戏脚本\闪光测试\audiolabel` 中创建 `闪光音效.audiolabel`；缺失的 `audiolabel` 会自动创建，不再弹出目录选择框。保存位置以点击保存时当前打开的脚本为准。
3. 若标签已经做好，把整个 `闪光音效.audiolabel` 文件夹复制到脚本旁的 `audiolabel`，保留其中的两个文件；手动复制时若没有 `audiolabel`，先新建这一层。
4. 核对最终目录结构，再在主窗口选择并连接游戏音频输入。声音匹配测试通过后，回到 `test.ecs` 运行下方脚本，并在等待期间触发游戏里的目标声音。

```text
D:\游戏脚本\闪光测试\
├─ test.ecs
└─ audiolabel\
   └─ 闪光音效.audiolabel\
      ├─ label.json
      └─ audio.wav
```

本例应当能在资源管理器中找到 `D:\游戏脚本\闪光测试\audiolabel\闪光音效.audiolabel\label.json` 和同目录的 `audio.wav`。`test.ecs` 与 `audiolabel` 是同级；`.audiolabel` 是装有两个文件的文件夹。

如果先制作标签，还没有打开或保存 ECS，点击保存后会提示“选择脚本所在文件夹（自动创建 audiolabel）”。选择 `D:\游戏脚本\闪光测试` 即可，最终保存位置仍是上图；稍后将 ECS 保存到这个文件夹再运行。取消选择不会创建目录，也不会丢失当前选区。

目录选择框始终选择准备存放 ECS 的文件夹，不要进入它下面用于存放标签的 `audiolabel` 子文件夹。程序始终在所选目录下面创建或复用 `audiolabel`；即使脚本目录本身恰好叫 `audiolabel`，也按这一规则处理，保持与 ECS 的查找路径一致。

```ecs
AUDIO_LOAD "闪光音效"
PRINT "开始识别，请在接下来的 8 秒内触发目标声音"
WAIT 8000
$score = AUDIO_SCORE("闪光音效")
PRINT "本轮最高分：" & $score
AUDIO_UNLOAD "闪光音效"
```

函数中只填制作时的名称 `"闪光音效"`，不填文件路径、`.audiolabel` 后缀或 `@`。此例在脚本 WAIT 期间后台识别，8 秒后读取已完成分析的累计最高分；不会命中后自动退出。尚无完整分析结果时为 0；加载失败或输入中断会报错，处理方法见[常见报错排查](#常见报错排查)。更多控制流程见[函数手册](Functions.md#声音匹配桌面-gui需连接游戏音频)。

常见放错方式如下，`…` 表示前面的父目录：

| 放置方式 | 问题与处理 |
|---|---|
| `…\闪光音效.audiolabel\test.ecs` | 脚本保存在标签内部，会从这里继续拼接 `audiolabel\…`。把入口脚本另存到上图的脚本目录，标签完整复制到其 `audiolabel` 下。 |
| `…\闪光测试\闪光音效.audiolabel\label.json` | 少了固定的 `audiolabel` 文件夹。在脚本同级创建这一层，再复制完整标签目录进去。 |
| `…\闪光测试\audiolabel\label.json` | 少了 `闪光音效.audiolabel` 这一层。保留标签文件夹及其中的两个文件。 |
| `…\闪光测试\audiolabel\audiolabel\闪光音效.audiolabel\label.json` | 多套了一层 `audiolabel`。按上图只保留一层。 |

导入的子脚本调用音频函数时，也使用入口脚本的目录。把 ECS 另存到其他目录或交给另一台电脑测试时，应一起复制包含 `test.ecs` 和 `audiolabel` 的整个脚本目录，保持两者的相对位置；只复制 ECS 文件不包含声音标签。

### 名称、时长与阈值

- 名称必须与标签内部保存的名称完全一致，包括英文大小写。只把 `闪光音效.audiolabel` 改名为 `闪光.audiolabel`，再调用 `AUDIO_LOAD "闪光"`，会因内部名称仍是“闪光音效”而失败。需要改名时，在编辑器打开原标签，修改名称并另存，然后在脚本中使用新名称。
- ECS 匹配和测试窗口使用同样的模板要求：0.15～10 秒，有足够的声音特征。可以保存或试听的片段未必满足匹配要求；静音、过短、过长的片段需要重新选区。
- 测试窗口调好的阈值不会保存到标签或自动同步到脚本。例如校准后采用 `92`，脚本应写 `IF AUDIO_SCORE("闪光音效") >= 92`。分数范围 0～100，比较使用未取整的值；应以实际正、负样本校准为准。

## 暂停、定位与快捷键

- 暂停后单击波形，或拖动红色游标，可以前后定位。“继续试听”从新位置播放到选区末尾。例如选区是第 3～5 秒，在第 4.2 秒暂停后单击第 3.6 秒，继续就从第 3.6 秒开始；保存仍保留第 3～5 秒。
- 游标只能定位到选区内，点击外侧会停在最近的选区边界。游标与裁剪边界重合时，可拖动顶部红色小手柄移动游标，拖动下方边界线调整裁剪。拖动其他波形区域仍用于重新框选，开始、结束时间也可以直接输入。改变选区会结束暂停状态，下一次试听从新选区起点开始。
- “停止试听”结束本次试听，保留当前位置供参考；下一次试听从选区起点开始。停止后也可单击波形指定新的试听起点。播放到选区末尾自动结束；在末尾继续不会自动循环。
- 空格切换播放／暂停／继续，长按只执行一次。即使焦点在“截取最近 10 秒”“开始录制”等按钮上，也不会触发这些按钮；尚无音频或正在录制时，空格不执行操作。标签名称和时间输入框保留自身的输入行为，要用空格控制试听时先点击波形或试听按钮。

## 实时匹配测试

1. 在主窗口的“游戏音频”面板连接输入，点击“声音匹配测试”。经典布局和卡片布局都有入口。
2. 点击“打开 WAV / 声音标签”，选择标签目录里的 `label.json`，也可以直接打开 WAV。测试模板需为 0.15～10 秒，包含完整且清晰的目标音效；静音和缺少有效特征的文件会被拒绝。
3. 点击“开始监听”，等候积累完整音效长度的新音频，然后在游戏中触发目标声音。监听从点击开始后的新数据计算，不会拿制作标签时的历史声音重复测试。
4. 查看“当前匹配分数”“本次最高分”和命中记录。当前分数是最近一批音频（通常约 100 ms）中最佳对齐位置的分数；没有完整、有效音频时显示 `—`。命中记录保存首次达到阈值时的分数、当时阈值和电脑检测时间，最近 100 条保留在内存。
5. 初始阈值是 85（合法范围 10～100），可以在监听时调整。连续高分只计一次；分数下降到阈值以下 5 分后才允许再次触发，并受“命中间隔”限制（默认 1 秒）。调整只影响后续音频，不会重新判定旧结果。
6. 点击“停止监听”保留结果；再次开始会清空本次结果。“清空结果”只重置界面统计，不重新触发正在响的同一次音效。关闭测试窗口会停止匹配，不会断开主窗口的音频输入。

先重复触发目标声音 5～10 次，检查是否漏报；再播放普通游戏声音和背景音乐，检查是否误报。根据两组分数调整阈值。如果分数混在一起，仅改阈值无法可靠区分，应重新截取背景干扰更少的模板。不要仅通过在电脑上回放模板来认定游戏识别已验证：真实游戏混音和音量变化还需单独测试。

匹配使用托管频谱模板比较：带滤波的 8 kHz 重采样、32 ms Hann 窗、10 ms 步长，合并各声道的频谱功率后提取归一化特征。左右声道反相不会因直接混为单声道而抵消。特征主要覆盖约 94～4000 Hz，对外分数范围为 0～100，表示相似度，不是出闪概率。归一化能减轻音量变化的影响，不能分离重叠的背景音乐、恢复被噪声淹没的音效或适应任意速度变化。

实时匹配复用已有采集设备，在后台线程处理。输入队列限制为 2 秒、4 MiB 或 256 块；积压、无效样本、断线、会话或格式变化以及超过 1 秒未收到新回调时清空旧数据，重新积累完整窗口。采集接口没有硬件缺包标记或精确样本时间戳，不能保证发现所有短暂中断；检测时间也不是精确的游戏事件时间。非 Windows 平台可以加载模板，暂不支持实时监听。

## 文件格式

每个标签是一个可整体移动的 `<名称>.audiolabel` 目录，包含：

- `audio.wav`：裁剪后的原始音频。
- `label.json`：版本（当前为 1）、名称、音频格式、采样帧数及 UTC 创建时间。

保存先写入临时目录，两个文件完整写入后一次性发布目录；文件写入失败不会留下一个看似完整的新标签，也不会覆盖旧标签。打开时校验 JSON 与 WAV 的格式和长度是否一致。修改标签后以新名称保存，保留原标签。

## 范围与边界

当前提供样本制作、实时匹配测试及 ECS 的 `AUDIO_LOAD` / `AUDIO_SCORE` / `AUDIO_UNLOAD` 函数。实时匹配窗口只展示分数和命中记录；脚本通过这些函数读取结果并明确决定后续动作。仍需使用实际游戏的正、负样本校准。背景音乐与目标音效同时出现时，裁剪不能把两者分离，应尽量采集背景干扰小的样本。

编辑器缓存借用现有 `IAudioCaptureSource`，不创建第二个采集设备。编辑器按完整采样帧裁剪，同时受 15 秒与 16 MiB 上限约束。断开、重连、格式变化、无效数据或超过 1 秒没有新回调时丢弃旧历史；陈旧数据不能作为“最近音频”截取。编辑器缓存不参与脚本检测；每个加载标签使用独立后台识别，峰值不受编辑器历史缓存影响。

## ECS 识别生命周期与限制

函数签名和完整流程见[函数手册](Functions.md#声音匹配桌面-gui需连接游戏音频)。可直接使用三个示例：[边按键边识别](../examples/audio-load-score.ecs)、[观察并打印峰值](../examples/audio-observe.ecs)、[卸载后重新开始一轮](../examples/audio-reload.ecs)。示例标签名为“医疗”，需要按相同目录规则准备；按键示例另需连接手柄。

- `AUDIO_LOAD(name)` 加载模板并建立本轮后台匹配后继续执行，不等待命中。识别在按键、普通 WAIT、循环期间持续运行，没有内置超时或自动退出。文件读取和模板准备需要时间，目标操作应放在 LOAD 后。本轮监听建立之前的声音不纳入结果。
- `AUDIO_SCORE(name)` 返回 DOUBLE，范围 0～100，为本次 LOAD 后已完成分析的累计最高相似度。读取不做现场分析、不等待、不清零、不消费结果，也不停止监听。尚无首个完整结果时为 0；有效静音也可得 0。60、92、40 的结果序列保留 92；经过 15 秒或目标声音结束后，只要输入持续有效，峰值仍保留。
- `AUDIO_UNLOAD(name)` 停止该名称的后台工作并释放本轮资源与结果。重新 LOAD 从 0 开始；重复 LOAD 已加载名称会报错，需先卸载。SCORE/UNLOAD 未加载或已卸载名称也报错。不同名称可同时加载，各自独立；没有固定标签数量上限，资源消耗随加载数量增加。
- `BREAK` 只退出循环，后台识别继续到 UNLOAD。脚本正常结束、异常或停止时自动清理全部本次运行的监听和后台任务；从不停止共享音频源。卸载会取消当前分析，并等后台退出后才完成，旧回调不能写入重载后的结果。
- 模板长度 0.15～10 秒决定单次匹配上下文，不限制监听生命周期。后台复用测试窗口的增量匹配器，每个标签的待处理队列最多 2 秒、4 MiB 或 256 块，另外只保留模板长度的特征和一个峰值标量；没有用于脚本回看的滚动历史。
- 输入断线/重连、格式变化、无效采样、队列积压、时间戳异常或超过 1 秒没有新数据，会终止本轮识别并保留错误。后续音频调用及脚本正常结束检查会报告错误，不返回旧高分或把错误当成 0。恢复输入后重新运行脚本；诊断窗口可自动重新积累音频，脚本不会自动恢复失效的一轮。
- 采集回调只复制有界音频数据，后台线程执行重采样、FFT 和比较。读取与 UI 都使用同一 0～100 标度，算法内部仍归一化为 0～1，在匹配结果出口换算一次；不按显示位数舍入后判断。诊断窗口的命中去重和冷却只影响界面记录，不改变脚本峰值。

每块音频携带不可变设备会话标识。监听起点使用单调回调时钟，跨越 LOAD 边界的首块按采样帧裁掉旧部分，迟到的旧设备数据和已经结束的轮次不会进入新轮。回调时间不是硬件采样时间戳，短暂硬件缺包和精确游戏事件时刻仍受驱动限制。

SCORE 只提供读取时已完成的结果。声音刚响起或分析尚未完成时不会等待补算；需要更多观察时间，由脚本作者安排 WAIT 或继续循环。后台不会延长脚本指定的 WAIT，也没有命中后的自动退出或超时宽限。当前 GUI 复用已连接的游戏音频；CLI 和单片机缺少此能力，会明确拒跑。

## 常见报错排查

报错中的完整路径就是脚本实际查找的位置，先用它与资源管理器里的实际文件对照。以下问题会报运行错误，不能作为“没有匹配到声音”继续处理。

| 日志或现象 | 检查与处理 |
|---|---|
| “请先保存脚本” | 先将入口脚本保存为 `.ecs` 文件，再按[首次使用步骤](#第一次在-ecs-中使用)放置标签并重新运行。 |
| “声音标签…无法加载”且提示找不到 `label.json` | 核对入口脚本位置、固定的 `audiolabel` 层、`<名称>.audiolabel` 层和调用名称。不要把 ECS 保存在标签文件夹里。 |
| 找不到 `audio.wav`，或 JSON 与 WAV 不一致 | 重新复制完整标签目录，两个文件必须来自同一次保存；也可从原始录音重新制作标签。不要只复制 JSON 或单独替换 WAV。 |
| “目录名称与标签元数据中的名称不一致” | 使用制作标签时的原名称（包括大小写），或在编辑器修改名称后另存；仅改文件夹名不能完成标签改名。 |
| “同名标签已存在” | 根据提示中的完整路径确认旧标签，修改编辑器中的名称后再保存；程序不会覆盖旧标签。 |
| 模板要求 “0.15 to 10 seconds” 或“标签没有足够的声音特征” | 重新截取 0.15～10 秒且包含完整、清晰音效的选区，先在匹配测试窗口确认能加载。 |
| 未连接音频、断开或重新连接、超过 1 秒没有新数据 | 检查主窗口音频输入及连接状态，恢复连续采集后重新运行脚本；重连不能续用旧一轮的检测结果。 |
| “尚未加载或已卸载；请先 AUDIO_LOAD” | 在读取或卸载前先加载同名标签；各次脚本运行互不继承。 |
| “已加载；请先 AUDIO_UNLOAD” | 本轮需要重新开始时先卸载再加载；重复 LOAD 不会偷偷清零峰值。 |
| “后台识别失败”或“分析积压” | 检查采集状态和处理负载，减少不需要同时识别的标签，恢复后重新运行。 |

刚 LOAD 后尚无完整分析结果时，SCORE 返回初始 0；持续有效静音完成分析后也可以得 0。设备没有送来音频包超过 1 秒则报错，不能通过降低阈值解决。

## 验证

自动化测试覆盖缓存回绕、原始样本裁剪、重连隔离、陈旧数据、文件往返、拒绝覆盖，以及编辑器试听/保存选区一致性与取消清理。手动录制另外验证起点裁剪、仅采新音频、手动停止、时间/内存上限、异常保留旧选区和订阅释放。无头界面测试验证空格不误触按钮、长按去重、输入框行为、暂停后单击/拖动游标再继续、边界裁剪、录制按钮与计时，以及两种语言与亮暗主题；手动截图用例可用于视觉检查。真实采集卡、实际扬声器试听和设备热拔插仍需实机验收。

匹配测试另外覆盖不同采样率和 PCM 格式、音量变化、反相立体声、任意分块边界、无关音效与静音、重复命中抑制、队列积压、断线后过期结果作废，以及窗口关闭时的取消与订阅清理。合成音频测试不能替代实际游戏音效的识别率验证。

ECS 测试覆盖新语法实际编译运行、旧接口拒绝、按键和 WAIT 期间后台识别、初始 0、峰值长期保留与重复读取、多个标签独立、标签路径、卸载重载、跨运行隔离、后台异常与停止清理。起点和长时间保留使用可控时钟验证；三份发布示例均参与编译运行，C VM 对缺失音频能力在加载期明确拒跑。
